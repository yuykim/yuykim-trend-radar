# 기술 트렌드 레이더 설계

상태: 연구 결과를 반영한 구현 제안. 구현·운영 성능은 아직 검증하지 않았다.

근거: [조사 범위](../../research/2026-10-18-tech-trend-radar/scope.md), [판정 통합표](../../research/2026-10-18-tech-trend-radar/claims.md), [결론](../../research/2026-10-18-tech-trend-radar/conclusion.md), [API 재확인](../../research/2026-10-18-tech-trend-radar/api-recheck.md).

## 목적과 가치 가설

사용자는 매일 현재 연구 동향, 새로 등장한 기술, 향후 성장 가능성을 검토할 후보를 확인한다. 초기 범위는 Physical AI이며 Robot Learning, VLA, World Model, JEPA를 출발점으로 삼는다. 주가·기업은 보조 정보다.

문헌 기반 탐색과 후보 생성에는 조건부 근거가 있으나 Physical AI의 미래 기술 성공 예측이나 사용자 효용은 입증되지 않았다(A01–A05, B01). 따라서 제품 가치는 다음 가설로 검증한다: 단순 논문 피드보다 유용한 새 기술을 더 일찍 발견하고, 중복·과장된 후보를 검토하는 시간을 줄인다. 아래 수치와 기술 선택은 논문이 입증한 결과가 아닌 설계 결정이다.

## 화면

요약 A는 네 영역으로 구성한다: 현재 연구 관심, 새 기술 후보, 향후 성장 관찰 후보, 커뮤니티에서 새로 포착한 논의. 기술 클릭 시 상세 B로 이동한다. 기업·주가는 상세 B의 접을 수 있는 보조 영역이다.

상세 B는 ‘무엇이 바뀌었나’, 이전 기술과의 차이, 근거 논문·최초 공개 시점, 연구 관심 추이, 커뮤니티 논의, 코드·모델·재현 상태, 반대 근거와 확인되지 않은 점을 보여준다. preprint/accepted/retracted를 구분하고 평가 결과의 데이터셋·metric·비교 조건을 원문 근거와 연결한다. 초록만 읽은 경우 본문 검증으로 표시하지 않는다.

graph view는 별도 탭이다. zoom < 1.2에서는 기술만, zoom >= 1.2에서는 기업 노드도 표시하며 선택 상태는 유지한다. 기술 간 관계는 `is_a`, `uses`, `combines_with`, `similar_to`로 구분한다. Robotics와 AI의 결합 설명은 분류·해석으로 기록하고 수학적 등식으로 취급하지 않는다. 기술→기업 관계와 기업 간 수익률 상관은 별도 레이어·범례로 전환한다. 수익률 상관으로 공통 기술 관계를 생성하지 않는다(B09–B13).

## 데이터 수집과 발견

논문 발견은 arXiv, 공개 학회 메타데이터/OpenReview, 인용·기관 보강은 OpenAlex를 우선한다. 각 connector는 실제 소량 조회로 권한·필드·페이지네이션을 확인한 뒤 활성화한다. 학회별 coverage manifest에 venue, 연도, 소스, 공개 범위와 누락을 적는다. OpenReview 밖의 학회는 공식 proceedings를 별도 확인하기 전 미수집으로 표시한다.

매일 07:00 Asia/Seoul에 갱신한다. 과거 24개월은 현재 지도 구성용으로 수집하고, 과거 시점 지표가 없는 소셜·stars·인용을 과거 예측 feature로 소급하지 않는다. 수집 누락은 0이 아닌 missing으로 보존한다. 한 소스가 실패해도 마지막 정상 결과와 기준 시각을 보여준다.

발견 경로를 둘로 나눈다.

1. 기존 기술: seed 용어·동의어·관련 venue로 논문을 추적한다.
2. 미지의 기술: cs.RO 및 인접 AI 범주의 넓은 표본에서 seed 밖의 신규 용어, 기존 topic에 배정되지 않은 문서 군집, 새롭게 늘어나는 topic 조합을 검토 후보로 올린다. 약어만 같다는 이유로 병합하지 않는다. 용어가 새로울 뿐 기존 기술의 이름 변경인 후보는 `rename_or_alias`로 보류한다.

최초 2주에 HN·Bluesky의 관련 게시물과 독립적 추가 발견 수를 측정한다. 표본 부족은 관심 부재로 해석하지 않는다. Reddit·Threads는 접근권한과 조건이 확인되면 추가하고 X는 초기 필수 수집원에서 제외한다. 사용자가 붙여 넣은 링크는 수동 후보로 받을 수 있다.

## 지표와 불확실성

‘연구 관심’은 수집 범위 내 최근 28일 unique 논문 비중과 직전 28일의 비중 차이, 절대 논문 수를 함께 보여준다. 분모는 같은 고정 도메인·같은 소스 coverage의 전체 문서 집합이다. 표본 5편 미만은 `low_support`로 표시하고 3/5/10편 기준 민감도를 평가한다. 학회 마감·공개일의 일괄 등록을 설명하고 소스 추가로 coverage가 바뀐 기간은 직접 비교하지 않는다(A02).

‘커뮤니티 관심’은 중복 URL·재게시·자동 배포를 구별한 고유 작성자·독립 원문 수다. 계정 유형 불명은 unknown으로 남긴다. 서로 다른 플랫폼 수치를 합산한 절대 인기 점수는 만들지 않는다(B01–B05).

‘새 기술 후보’는 최초 관측일, 알려진 최초 공개일, 독립 자료 수, seed 밖 발견 경로, 기존 기술과의 차이를 제시한다. ‘새로 수집됨’과 ‘새로 등장함’을 구별하며 신규 후보는 검토 전 사실로 확정하지 않는다.

‘향후 성장 관찰 후보’는 연구 비중 변화, 독립 연구기관 수, 코드·모델 공개 여부를 설명 가능한 feature로 제시한다. 초기에는 예측 확률이나 성공률을 표시하지 않는다. citation·산업 성공·미래 concept 연결은 서로 다른 target이다(A03–A08, B16–B18). LLM은 근거가 붙은 요약·용어 후보만 제안하고 자동 확정·원문 없는 수치 생성은 하지 않는다.

## 저장 모델과 시간

SQLite에 다음을 저장한다: documents, document_versions, entities, aliases, document_entities, evidence_edges, observations, candidates, reviews, source_runs. 회사와 상장 증권은 별도 entity이며 ticker·거래소·모회사 관계를 구별한다.

각 자료에 `published_at`(해당 버전 공개일), `first_public_at`(확인된 최초 공개일), `observed_at`(우리 수집일), `available_at`(해당 feature를 알 수 있었던 시점), `retrieved_at`, source URL을 둔다. 알 수 없는 날짜는 null이다. 예측 입력은 available_at <= cutoff만 사용하고, 이력을 확보하지 못한 현재 인용·현행 topic 분류·현재 embedding/vocabulary는 strict historical backtest에 쓰지 않는다. retrospective analysis와 prospective evaluation을 구별한다.

모든 edge는 relation, source URL, 근거 발췌 또는 위치, 해당 시점, extraction method, review status를 가진다. 논문 저자 소속은 `authored_research`이며 상용 도입의 증거로 바꾸지 않는다. ETF 편입과 증권사 섹터는 후보 분류이며 세부 기술 보유 증거가 아니다.

## 가치 검증과 진입 기준

개발 전 30건의 관련/무관·동의어·중복·새 이름 후보를 수동 검토한 fixture를 만든다. 미래 정보가 들어간 fixture는 회고적 검증으로 명시한다. 이후 4주간 prospective 평가를 수행한다.

baseline은 동일 수집 코퍼스의 날짜순 seed 키워드 피드다. 확장 후보 생성은 동일 알림 예산(하루 최대 5건)에서 비교하고, broad feed의 별도 비교도 남겨 수집 범위 확대 효과와 순위화 효과를 구분한다. 사용자는 시스템 점수를 숨긴 후보를 검토하고 ‘이전에 알았는지’, 관련성, 기존 대비 차이, 유용성을 기록한다. 이는 개인 1명의 효용 평가이며 일반 사용자 성능으로 확대하지 않는다.

제안 Go 기준: (1) 핵심 수집 작업 성공률 95% 이상, (2) 유용성 precision@5가 baseline보다 10 percentage points 이상 높음, (3) 사용자가 몰랐던 유용 후보 주 2건 이상, (4) baseline에서도 발견된 공통 후보의 발견 시차 중앙값 1일 이상 단축, (5) 하루 검토시간 중앙값 10분 이하. baseline에 영원히 안 잡힌 후보는 추가 발견으로 별도 집계하며 가상 시차를 부여하지 않는다. 표본 부족이면 inconclusive로 두고 확장한다. 기준은 실험 전에 잠근다.

가장 초기 논문 공개와 시스템 탐지 사이의 지연도 보고하되, 이를 경쟁 서비스 대비 선행성으로 부르지 않는다. 확장 평가에서는 향후 90일 신규 연구기관 확산 등 target을 사전에 정하고, 그 horizon이 끝난 뒤에만 미래 성장 성능을 평가한다.

## 단계와 기술 선택

1차 MVP는 수집·정규화·근거·리뷰·요약/상세 화면과 단순 graph다. 다음 단계에서 커뮤니티의 추가 가치, graph 탐색 편익, 기업·주가를 순서대로 검증한다. graph의 기업 노드는 실제 근거가 있는 작은 수동 seed로 먼저 연결할 수 있다. 자동 대규모 기업 추출은 뒤로 둔다.

Python + FastAPI + SQLite backend, React + TypeScript + Vite + Cytoscape.js frontend를 제안한다. 초기 순위화는 규칙 기반이며 graph database·vector database는 도입하지 않는다. embedding/복잡한 예측기는 단순 기준선을 넘어설 때만 추가한다. 라이브러리 버전은 구현 시 공식 문서와 호환성을 확인하고 lockfile로 고정한다.

API·hosting 유료 결제는 초기 설계에 포함하지 않는다. OpenAlex는 무료 예산을 넘기기 전에 중단하고, 선택 LLM 요약은 호출을 끄더라도 원문 기반 화면이 동작하게 한다. Windows Task Scheduler는 중복 실행 lock·누락 작업 복구·로그를 포함한 명시적 설치 절차를 제공한다.

## 보조 금융 기능

기업과 증권 식별·기술 근거가 검토된 이후 토스의 조회 기능만 연결한다. 시세 기준 시각·통화·거래소·지연 상태를 표시한다. 수익률 상관은 같은 시장/통화 기준의 수정 종가가 확보된 경우 우선 최근 120거래일, 공통 관측일 최소 60일로 계산한다. 가격 수준 상관은 사용하지 않는다. 결측일 forward fill·해외/국내 비동기 종가의 단순 혼합을 피하고 비교 불가 사유를 표시한다. 조정 방식 불명확 시 상관 레이어를 비활성화한다. 기업 연결·주가 상관은 미래 수익률의 증거가 아니다(B12–B15).

## 전역 제약

- 초기 도메인은 Physical AI, 사용자는 개인 1명이다.
- 주가 예측·자동매매·주문 API는 구현 범위 밖이다.
- 갱신 기준은 매일 07:00 Asia/Seoul이다.
- 미확인 값은 null/unknown, 수집 누락은 missing으로 보존한다.
- 모든 후보와 관계는 source URL·기준 시점·검토 상태로 추적할 수 있어야 한다.
- API secret은 backend 환경변수에서만 읽고 frontend·로그·fixture에 포함하지 않는다.
- 초기 유료 API·hosting 결제는 하지 않는다.
- 개발·검증은 Windows PowerShell에서 실행 가능해야 한다.
